# Deployments Module

Manages external deployment providers and their run history. A **DeploymentProvider** holds the configuration (URL, type, options) for an external build/deploy hook. Triggering a provider fires an HTTP POST to that URL and records the outcome as a **Deployment** run.

All endpoints are restricted to `ROLE_ADMIN`.

## Domain Entities

### `Deployment`

A single deployment run — records the outcome of firing a provider's build hook.

| Property      | Type                    | Notes                                              |
|---------------|-------------------------|----------------------------------------------------|
| `id`          | `string`                | UUIDv7, generated by constructor                   |
| `providerId`  | `string`                | UUID of the triggered DeploymentProvider           |
| `status`      | `DeploymentRunStatus`   | Starts as `PENDING`; set to `RUNNING` then final   |
| `log`         | `?string`               | HTTP response body or error message; null initially|
| `triggeredBy` | `?string`               | UUID of the user who initiated the run             |
| `startedAt`   | `\DateTimeImmutable`    | Set at construction                                |
| `completedAt` | `?\DateTimeImmutable`   | Set by `complete()`; null while running            |

Key method: `complete(DeploymentRunStatus $status, ?string $log)` — sets the final state and captures the completion timestamp in one call.

### `DeploymentProvider`

A configured external deployment target.

| Property    | Type                     | Notes                                              |
|-------------|--------------------------|----------------------------------------------------|
| `id`        | `string`                 | UUIDv7, generated by constructor                   |
| `name`      | `string`                 | Human-readable display name                        |
| `type`      | `DeploymentProviderType` | Integration kind                                   |
| `url`       | `string`                 | Webhook / build-hook URL to POST to                |
| `options`   | `?array`                 | Extra config (e.g. custom headers); null = none    |
| `isActive`  | `bool`                   | Defaults to `true`; disabled providers cannot run  |
| `createdAt` | `\DateTimeImmutable`     | Set at construction                                |
| `updatedAt` | `?\DateTimeImmutable`    | Null until first mutation; refreshed on any setter |

Mutating setters (`setName`, `setUrl`, `setOptions`, `setIsActive`) all call the private `touch()` helper to refresh `updatedAt`.

Both entities use a `reconstitute()` static factory for loading from persistence without resetting identity or timestamps.

## Enums

### `DeploymentRunStatus`

Lifecycle states of a run record. Valid transition: `PENDING → RUNNING → SUCCESS | FAILURE`.

| Case      | Value       | Description                                        |
|-----------|-------------|----------------------------------------------------|
| `PENDING` | `'pending'` | Created, HTTP request not yet sent                 |
| `RUNNING` | `'running'` | HTTP POST in flight                                |
| `SUCCESS` | `'success'` | Provider responded with 2xx                        |
| `FAILURE` | `'failure'` | Non-2xx response, or request threw an exception    |

### `DeploymentProviderType`

| Case      | Value       | Description                                   |
|-----------|-------------|-----------------------------------------------|
| `WEBHOOK` | `'webhook'` | Generic HTTP webhook — POST to a custom URL   |
| `NETLIFY` | `'netlify'` | Netlify build hook                            |
| `VERCEL`  | `'vercel'`  | Vercel deploy hook                            |
| `CUSTOM`  | `'custom'`  | Caller-defined behaviour via options payload  |

## REST Endpoints

| Method   | Path                   | Description                                             | Response            |
|----------|------------------------|---------------------------------------------------------|---------------------|
| `GET`    | `/deployments`         | Paginated list of deployment providers                  | 200 data + meta     |
| `GET`    | `/deployments/{id}`    | Single deployment provider by UUID                      | 200 data or 404     |
| `POST`   | `/deployments`         | Create a new deployment provider                        | 201 data or 422     |
| `DELETE` | `/deployments/{id}`    | Delete a deployment provider by UUID                    | 204 or 404          |
| `POST`   | `/deployments/{id}/run`| Fire the build hook; persist and return the run record  | 201 data or 404/422 |

### Query Parameters (`GET /deployments`)

| Parameter | Type  | Default | Description              |
|-----------|-------|---------|--------------------------|
| `limit`   | `int` | `25`    | Records per page (min 1) |
| `offset`  | `int` | `0`     | Pagination offset        |

### `POST /deployments` — Request Body

```json
{
  "name":     "Production Vercel",
  "type":     "vercel",
  "url":      "https://api.vercel.com/v1/integrations/deploy/...",
  "options":  { "headers": { "Authorization": "Bearer ..." } },
  "isActive": true
}
```

`name`, `type`, and `url` are required. `options` and `isActive` are optional (default: `null` / `true`).

## Trigger Workflow (`TriggerDeploymentHandler`)

1. Load provider by UUID — throw `DeploymentNotFoundException` if missing.
2. Check `isActive` flag — throw `DeploymentProviderInactiveException` if false.
3. Persist a `Deployment` run record with status `RUNNING`.
4. `POST` to `provider.url` with a 15-second timeout (headers from `options.headers` if present).
5. Determine outcome: 2xx → `SUCCESS`; non-2xx or exception → `FAILURE`.
6. Call `deployment.complete($status, $log)` and persist the updated record.

## Access Control

All endpoints require:
- A valid JWT access token (`ApiScope::AUTHENTICATED`)
- Clients: `WEB` or `CLI`
- The `ROLE_ADMIN` Symfony role

There are no user-scoped paths — every action in this module requires admin privileges.
